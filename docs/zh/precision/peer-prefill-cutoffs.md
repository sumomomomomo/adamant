# 实验性三 GPU 预填充阈值

[English](../../precision/peer-prefill-cutoffs.md)

单槽服务在启用 `--prefill-native-next`、额外专家辅助卡实际参与计算、具有两个专家层级、
主卡与第一个对等卡性能相近且专家非独占放置时，使用下列实测阈值。
其他配置保留现有策略。这些功能仍属于默认关闭的实验功能。

| 实际分块 token 数 | 原策略 | 调整后策略 |
|---|---|---|
| 开始流式融合预填充 | 2,560 | 6,144 |
| 额外对等卡处理的最大路由分块 | 2,048 | 6,143 |
| 第一个对等卡融合辅助路径的最大分块 | 4,096 | 4,096 |

流式阈值以下，MMQ 将路由到的专家分配给主卡和两个对等卡计算。
阈值以上，主卡通过流式传输读取非常驻专家。调整后的配置没有符合融合辅助路径条件的
分块，因为该路径的上限低于流式阈值，因此不分配其未使用的设备缓冲区。
此实验模式以外的配置仍可使用原辅助策略。阈值针对实际分块；检查点和单独处理的
最后一个 token 都可能使分块短于完整提示词。

运算内核、模型权重、PLE 精度、KV 格式和解码策略均未改变。
中等长度提示词会在现有 MMQ 和融合运算之间切换，缓冲区预留也可能改变专家布局。
因此数值结果及贪心响应可能变化。

## 开发比较

本节所有结果均使用 RTX 3090 Ti / RTX 3090 / RTX 3080，强制功耗上限为
400 / 320 / 250 W，配置 int8 KV、完整 Q8_0 PLE 和 DFlash2。
这些是代理运行的开发测量，不是正式基准。

筛选比较了 2,560、4,096、6,144 和 8,192 的流式阈值，以及扩展至 8,192 token 的
融合辅助路径。各组预留相同的对等缓冲区，初始专家布局均为 7,669 / 9,331 / 7,576，
RAM 副本固定为 20 GiB，关闭自适应和提示词前缀复用。
三次长提示词预热后，每个长度测量两个源代码提示词。
速率按总 token 数除以引擎总耗时计算。

| 精确提示词 token 数 | 原策略，tok/s | 调整后策略，tok/s |
|---|---:|---:|
| 2,048 | 1,619.8 | 1,602.8 |
| 3,072 | 1,100.2 | 1,647.8 |
| 4,096 | 1,314.7 | 1,670.9 |
| 5,120 | 1,347.1 | 1,673.2 |
| 6,144 | 1,598.5 | 1,682.5 |
| 8,192 | 2,087.8 | 2,050.8 |
| 16,384 | 3,714.4 | 3,662.5 |
| 32,768 | 4,483.2 | 4,416.0 |

将路由阈值提高至 8,192 token 没有改善 8K 吞吐量。
将融合辅助路径扩展至 8,192 后，其 8K 结果降至 1,767.7 tok/s。
各组 512-token 解码检查均使用相同的 157 个验证窗口：原策略与调整后策略分别为
24.23 / 24.06 ms/窗口，即 134.6 / 135.5 tok/s。
长提示词及解码时序的微小变化需要交替比较，不能据此声称没有开销。


使用标准 `basalt-bench` 测试数据、固定预留及相同专家布局的 A/B/B/A 检查中，
4,191-token 提示词分别达到 1,113.3 和 1,598.7 tok/s（+43.6%）。
每个进程的 prose 测试均通过 472 个窗口生成相同的 1,072 token：
分别为 22.122 和 22.409 ms/窗口（45.20 和 44.63 次/秒），诊断配置的解码慢 1.3%。
这不能证明解码没有开销；普通服务分配另行检查。

## 复现与验证

`--diag-prefill-cutoffs STREAM,EXTRA,LARGE` 是 A/B 诊断选项，不是服务配置建议。
流式及融合辅助上限最大为 8,192，额外对等卡上限最大为 6,144，且必须严格小于 STREAM。
所有诊断组都为第一个对等卡预留 8,191 个路由 token、为额外对等卡预留 6,144 token，
并为融合辅助路径预留 8,192 token，因此修改所选阈值不会改变这些预留量。
仍需检查实际专家布局。普通服务按所选策略分配缓冲区。此诊断默认关闭。

`prefill_policy_test` 检查配置适用条件、阈值验证和预留范围。
四个 `prefill_layout_*` 测试覆盖阈值附近的缓冲区布局。
`prefill_fused_peer_test` 在专家归属碎片化、为空或完整的情况下逐字节比较返回行。
没有引入新的运算内核。

BF16 参考使用 512-token 上下文，在 256-token 前缀之后对解码半段评分。
可在此比较强制流式运算与普通路由运算，但不能直接测量 4K 或 6K 上下文的 BF16 质量。

## BF16 质量

在相同的 400 / 320 / 250 W 上限下，流式对照逐字节复现了已有 100 分块测量中
前 20 分块的全部 5,100 行。路由候选通过 `basalt-bench --quality` 对全部 100 分块评分。
这些比较使用固定预留诊断。

| 指标，25,500 个评分位置 | 流式对照 | 路由候选 |
|---|---:|---:|
| PPL | 3.30826788 | 3.30806771 |
| 平均 BF16 KL 散度 | 0.09611791 | 0.09615407 |
| BF16 top-1 一致率 | 89.76471% | 89.71765% |

PPL 变化为 -0.00605%，平均 KLD 变化为 +0.00003615，top-1 一致率变化为
-0.04706 个百分点。实测差异很小，但不能证明逐位等价或实际 4K 上下文的 BF16 对齐。

## 普通服务验证

另一次 A/B/B/A 比较使用原始二进制与最终自动策略，各自采用普通缓冲区分配。
初始专家布局均为 7,669 / 9,331 / 7,576，RAM 副本固定并关闭自适应。
每个进程运行三次标准 prose 测试。功耗上限仍为 400 / 320 / 250 W。

两种模式每次生成的 token 数及验证窗口数相同。
每种模式六次请求汇总后，原始与调整后版本的结果分别为
20.81377 / 20.57810 ms/验证窗口及 109.1329 / 110.3827 tok/s。
普通分配没有复现上方诊断配置的解码减速；实测窗口耗时下降 1.13%。

最终自动策略还在普通分配下运行全部 100 个 BF16 参考分块：
PPL 为 3.30383093，平均 KLD 为 0.09661079，top-1 一致率为 89.69020%。
全部 25,500 行与先前验证的普通路由预填充参考完全一致。
固定预留诊断在质量运行中使用了不同的对等卡布局，因此其行值不能与此服务测量互换。
