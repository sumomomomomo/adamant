# 双槽位 MTP 窗口扫描

[English](../../precision/mtp-slots.md)

以下为代理开发测量，使用 RTX 3090 Ti / RTX 3090 / RTX 3080，强制功率限制为
400 / 320 / 250 W，int8 KV、Q8_0 PLE、两个完整上下文槽位、22.0 GiB 常驻预算，
以及额外对等卡的路由预填充。保持自动专家布局和自适应，禁用提示词及对话缓存。
所有被测引擎启动时均无 SSD 专家溢出。

对照为 `--spec 8`、`--mtp-max-t 0`、`--suffix-draft 0`。
MTP 上限为零时跟随 `spec`；`spec=1` 为不使用草拟的基线。

## 测量方法

两个确定性计数提示词各生成 2,048 token。联合解码吞吐仅统计从第二个流首次输出
到第一个流最后输出之间两个槽位的 token。另一场景先启动生成 8,192 token 的
计数回复，再提交未缓存的 21,306-token 园艺提示词。解码吞吐仅统计该提示词提交
至其首次输出之间的区间。每次运行中，原有解码器均持续活跃至整个预填充结束。

每 20 ms 采样一次各槽位的实际已生成 token 计数，不以内容事件数代替 token 数，
因此区间边界存在采样误差。流式间隔使用客户端观察到的非空内容事件；一个事件可能
包含多个 token。这不是精确的引擎逐 token 间隔。

初始顺序为 8、4、1、2、6，每次先双路解码、再重叠预填充。
随后按 6、8 的顺序复测最强非对照候选及对照，每次先重叠、再双路解码。
未固定缓存布局；场景顺序使自适应历史不同。因此这是部署配置比较，
不是独立算术计时。计数提示词有利于可预测的草拟。

## 结果

6 和 8 的范围表示两次运行；其他配置只有一次。
每一行的功率限制均为 400 / 320 / 250 W。

8 与 6 的平均联合解码分别为 210.1、201.2 tok/s；预填充期间平均解码分别为
211.2、181.5 tok/s。平均预填充耗时为 37.83、36.40 秒。
预填充期间最大事件间隔为 8 时 487 ms、6 时 439 ms。未指定硬性流式间隔阈值。

对于吞吐优先的偏好，保持 8，并接受上述实测暂停代价。
8 的双路解码复测出现一次 1.23 秒暂停，因此这不代表延迟均匀。
要确定通用最优值，还需更多散文、工具调用负载及重复运行。

此配置扫描不代表进行了新的算术质量检查。
