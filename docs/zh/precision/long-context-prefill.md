# 长上下文下的 RAM 后备预填充

[English](../../precision/long-context-prefill.md)

## 容量与调度

主专家缓存、弹性 KV 和预填充工作区共享 VRAM。如果后备缓存尾部仅按每槽一个配置
预填充分块长度计算，对话超过该长度后就可能耗尽空间。此时即使 `--read-live-chunk`
要求更大分块，调度器也会退回 256-token 预填充分块。

对未做层拆分、带预算的批处理服务，RAM 后备现在包含配置的实时分块工作区，以及
每个主卡槽位弹性 KV 的最大增量（`max_cells`），包括附加 KV 区域。
后备区域可超过原来的提示词专用借用区域，但受 GPU 缓存及常驻 RAM 预算限制。
它不会预先分配最大 KV，也不增加预算。后备副本和自适应空闲位置先于按热度排序的
专家副本获得预算。RAM 不足时仍可能只保留较短尾部，并缩小分块。
当前所有权检查和自适应后备保护继续生效。

`--read-beside` 让短提示词也使用现有后台读取路径。不启用时，不超过 16,384-token
阈值的读取可能阻塞解码。共享 GPU 资源可能使预填充本身变慢，但保持流式输出响应。
此标志仍需显式启用；后备修复不改变默认调度策略。

## 开发 A/B

这些是普通分配下的代理开发检查，不是正式性能基准。
RTX 3090 Ti / RTX 3090 / RTX 3080 的强制功率限制为 400 / 320 / 250 W。
两版本均使用两个 262,144-token 槽位、int8 KV、MTP 窗口 8、Q8_0 PLE、
32,768-token 预填充容量、额外预填充对等卡、自适应及 21.5 GiB RAM 预算。
启用提示词缓存，禁用磁盘对话缓存，每个新准入提示词均未命中缓存。
不同合成提示词前缀防止被测请求之间复用。候选版本额外启用 `--read-beside`。
测试先旧后新，保持自动布局；无法单独区分后备及调度的作用。

先提交约 80K-token 提示词，要求生成长篇技术报告。开始解码后，向第二槽位提交新的
9,622 或 19,279-token 提示词。解码速率使用每 20 ms 采样的槽位实际已生成计数，
区间从第二请求提交至其首次输出。流式间隔基于客户端内容事件，事件和 token 不一定
一一对应。每种情况各运行一次。

启动时所有专家仍位于 GPU 上。这不代表所有预填充文件读取均已消失。
