# 大分块对等 GPU 预填充原型

[English](../../precision/large-peer-prefill.md)

此诊断原型对不超过 4,096 个未缓存 token 的分块，将 Flash-Next 专家的预填充计算
分配给主 GPU 和第一个对等 GPU。更大的分块保留普通的主 GPU 专家计算。默认关闭。
注意力、路由、共享专家、HC 写入、视觉和 DFlash2 仍在主 GPU 上运行。
其余专家层级保留现有职责。

启用 native-next 且两个专家层级均参与计算时，[实验性三 GPU 阈值](peer-prefill-cutoffs.md)
会为中等分块选择路由路径。

## 执行

原生融合路径通过便携页锁定内存，发送已量化的激活及主 GPU 的原始行映射和分组表。
对等 GPU 使用现有内核计算本卡常驻专家的互不重叠区间，并返回未改变的 F32 行。
主 GPU 从权重流和融合内核启动中排除这些专家，等待返回的行，再按原始路由顺序
执行现有合并。融合格式覆盖范围之外的层保留现有布局。
量化、运算及归约顺序均保持不变。

阈值针对每个实际预填充分块，与对话总长度无关。较小分块使用现有的仅路由专家对等
计算；融合扩展只对阈值以内、走权重流式路径的分块中受支持的层生效。
因此，长请求的最后一个分块若不超过 4,096 token，仍可使用辅助卡。

传输缓冲区最多覆盖 4,096 token，并在专家布局前预留辅助卡显存。
融合路径的主机缓冲区在 RAM 专家副本定容前预留。原型保留各专家的独立输出，
不在对等卡上合并贡献，也不压缩返回的浮点数。因此传输开销可能超过节省的计算。

## 诊断比较

`--prefill-peer-large 0` 使用普通路径。模式 `1` 启用原型；模式 `2` 分配相同缓冲区，
但使用普通计算布局，供 A/B 比较。两种诊断模式都在层级布局前将对等卡可用容量
向下取整到 256 MiB 边界。比较贪心输出或性能时必须关闭自适应，并检查实际专家布局。
这些模式是开发诊断，不是推荐的服务设置。

## 验证

`prefill_fused_peer_test` 将返回的专家行与现有仅主卡融合内核的结果逐字节比较。
覆盖 IQ4_XS、IQ3_XXS 和 IQ2_S gate/up、IQ4_NL down、全零输入、未使用专家、碎片化专家归属、
对等卡不持有专家及持有全部专家，分块长度为 33、257、4,096 和 16,384 token。
运算内核未改变，其现有 CPU 参考测试仍然适用。


## 完整模型开发检查

下方原始测量中，混合 UD-IQ4_XS 模型包的 48 个专家层有 13 层受融合格式支持；其余 35 层在大分块下
保留主 GPU 的普通 MMQ 路径。需显式启用的[长提示词预填充实验](long-prefill.md)也覆盖这些层的 Q5_0 下投影。
探索性检查发现，扩展旧 MMQ 对等分组不能保持贪心输出
一致，因此本原型排除了该改动。

A/B/B/A 比较使用 RTX 3090 Ti / RTX 3090 / RTX 3080，功耗上限分别为
375 / 320 / 250 W。预留缓冲区相同，主卡容量固定，对等卡专家布局一致，关闭自适应及
提示词前缀复用。全部 24,576 个解码专家均位于显存中。提示词暂存仍包含 RAM 和文件访问
及文件缓存冷热效应；这些是开发结果，不是正式基准。下表速率按每组两次运行的总 token
数除以引擎总耗时计算。

以下数据来自添加 4,096 token 阈值之前、未限制长度的原型。

| 提示词 token 数 | 普通计算，相同缓冲区 | 未限制长度的原型 | 变化 |
|---|---:|---:|---:|
| 4,068 | 774.5 tok/s | 914.0 tok/s | +18.0% |
| 8,164 | 1,592.6 tok/s | 1,555.6 tok/s | -2.3% |
| 16,356 | 2,307.9 tok/s | 1,869.8 tok/s | -19.0% |

在相同功耗上限下，2,048 token 生成检查的速率分别为 162.3 和 159.5 tok/s。
四次运行中的全部五个回答均一致：三个文本提示词、一次 2,048 token 生成和一个图像提示词。
大分块日志确认对等 GPU 返回了已计算的专家行。原型默认保持关闭。

启用原型后，包含图像的后续对话、RAM 淘汰、进程重启后的磁盘恢复及图像语法约束解码
也均通过，DFlash2 候选持续被接受。

## 限长策略开发检查

另一次针对限长策略的 A/B/B/A 检查使用相同的功耗上限
（375 / 320 / 250 W）、相同的 4,096 token 辅助卡缓冲区及专家布局，
关闭自适应和前缀复用。四次运行中的全部七个用例输出均一致：
512、2,048、4,096、4,097、4,098 和 16,384 token 提示词，以及一个
生成 2,048 token 的用例。运算内核未改变。

关闭提示词检查点时，服务器单独处理提示词的最后一个 token。因此，4,097 token 的冷提示词会执行
一个 4,096 行的分布式分块；4,098 token 提示词会执行一个 4,097 行的
仅主卡分块。日志确认了阈值两侧的路径。启用提示词检查点时，分块方式可能不同；
阈值仍针对每个实际分块。

| 提示词 token 数 | 普通计算，相同缓冲区 | 限长原型 | 变化 |
|---|---:|---:|---:|
| 4,096 | 962.6 tok/s | 1,083.4 tok/s | +12.6% |
| 4,097 | 1,109.8 tok/s | 1,155.5 tok/s | +4.1% |
| 4,098 | 1,098.9 tok/s | 1,107.0 tok/s | +0.7% |
| 16,384 | 1,843.4 tok/s | 1,835.0 tok/s | -0.5% |

生成 2,048 token 的用例测得 200.1 与 197.3 tok/s（-1.4%），
均使用 340 个验证窗口，每窗口输出 6.02 token。
平均窗口耗时分别为 30.10 与 30.53 ms；其中一次原型运行较慢
（30.85 ms，而另一次为 30.21 ms）。这些开发检查不能证明普遍的预填充收益，
也不能证明解码没有代价。全局默认值保持不变。
限长缓冲区在辅助卡预留 443 MiB 显存和 412 MiB 页锁定主机内存；
分配日志中的数值向下取整到完整 MiB。

## 在流式阈值以下强制融合执行

一次开发 A/B/B/A 检查在 256、512、1,024 和 2,048 token 提示词上，比较普通
仅路由专家 MMQ 与强制流式融合对等路径。功耗上限为 375 / 320 / 250 W。
每个进程中，每种长度使用两个提示词，关闭前缀复用、提示词检查点及自适应。
四个进程在各 GPU 上的专家数均为 7,669 / 9,331 / 7,576，辅助卡缓冲区及预留
空间相同。全部 24,576 个解码专家均位于显存中。

实验为未受融合支持的 35 层保留普通 MMQ 辅助卡计算。强制流式执行也改变暂存、
分组、CPU 回退及路由预取；因此测量的是完整强制路径，而非独立融合内核吞吐量。
数据仍包含 RAM/文件暂存及其缓存效应。

| 提示词 token 数 | 仅路由专家 MMQ | 强制融合对等路径 | 变化 |
|---|---:|---:|---:|
| 256 | 471.6 tok/s | 153.9 tok/s | -67.4% |
| 512 | 894.8 tok/s | 307.1 tok/s | -65.7% |
| 1,024 | 1,133.9 tok/s | 576.5 tok/s | -49.2% |
| 2,048 | 1,419.5 tok/s | 983.8 tok/s | -30.7% |

日志确认，在 255、511、1,023 和 2,047 token 分块中，融合辅助卡返回了计算行。
一个 512 token 用例和一个 2,048 token 用例出现稳定的贪心输出差异：普通路径两次
运行互相一致，强制路径两次运行也互相一致。未进行 BF16 PPL/KLD 检查，因此本实验
不能证明切换小分块路径后的质量等效性。

共同的 4,097 token 提示词使两个配置在生成 2,048 token 前，执行相同的
4,096 行融合预填充路径。生成输出一致，速率为 170.9 与 172.6 tok/s（+1.0%）。
不保留强制小分块路径。低于 2,560 token 流式阈值时继续使用仅路由专家共享；
融合扩展仍只覆盖不超过 4,096 token 分块中受支持的层。
