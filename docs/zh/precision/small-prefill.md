# 短提示词预填充调查

[English](../../precision/small-prefill.md)

开发目标是在 256 和 512 个未缓存 token 下达到每秒 1,000 个提示词 token。
测试系统使用 RTX 3090 Ti / RTX 3090 / RTX 3080，功耗上限分别为
375 / 320 / 250 W，模型为混合 UD-IQ4_XS，使用完整 Q8_0 PLE 表、int8 KV
及 DFlash2。短分块继续使用仅路由专家 MMQ 和第一个辅助卡的专家共享。

## 性能分析

Nsight Systems 在预热后，记录两个 256 token 和两个 512 token 提示词的
CUDA 及系统运行库活动，每个请求生成一个 token。关闭采样和 CPU 上下文切换跟踪。
分析器会增加开销；跟踪耗时是诊断观察值，不是正式吞吐量数据。

记录包含 76,119 次 CUDA 内核启动调用，其中 48,726 次为逐专家原生权重收集。
跨线程的内核启动 API 耗时合计 529 ms。此值不能视为关键路径上的 CPU 开销。

| 提示词 token 数 | 主机至主卡流量 | GPU 传输活动耗时 |
|---|---:|---:|
| 256，第一个提示词 | 5.122 GB | 434.6 ms |
| 256，第二个提示词 | 5.146 GB | 433.5 ms |
| 512，第一个提示词 | 7.711 GB | 681.1 ms |
| 512，第二个提示词 | 7.723 GB | 674.1 ms |

流量按每个提示词的嵌入广播到下一个提示词的嵌入广播之间统计，包含一个 token 的
解码尾部及请求间准备。主卡链路为 PCIe 4.0 x8，有效传输带宽为 11.3–11.9 GB/s。
传输可以与内核重叠，因此不能把传输耗时与内核耗时直接相加作为端到端分解。
在传输量不变时，256 ms 和 512 ms 的目标分别要求约 20.0 GB/s 和 15.1 GB/s
的主机至主卡流量吞吐量，尚未考虑依赖及其他操作。

## 实验

比较固定 GPU 专家布局为 7,669 / 9,331 / 7,576 个条目，RAM 专家副本为 24 GiB。
关闭前缀复用、提示词检查点、停放缓存及自适应。运算内核和 MMQ 分组成员不变。
现有 K-quant MMQ 测试通过 CPU 参考检查；分组收集与逐专家收集的结果逐字节一致。

分组收集候选同时合并主卡及第一个辅助卡的权重收集。A/B/B/A 比较中，每个进程对
每种长度使用两个提示词。下表 PP 速率按各配置的总 token 数除以引擎提示词总耗时计算。

| 提示词 token 数 | 逐专家收集 | 分组收集 | 变化 |
|---|---:|---:|---:|
| 256 | 510.1 tok/s | 516.5 tok/s | +1.3% |
| 512 | 726.2 tok/s | 724.6 tok/s | -0.2% |
| 1,024 | 920.5 tok/s | 918.7 tok/s | -0.2% |
| 2,048 | 1,225.7 tok/s | 1,228.0 tok/s | +0.2% |

单独的 2,048 token 生成用例测得 170.9 与 173.9 tok/s。
四次运行中的所有生成回答均一致。

随后两次 A/B 初筛使用 CUDA 批量传输提交：先只处理常驻页锁定源，再加入文件暂存
缓冲区。结果均不足以支持进一步的性能收益声明：256/512 token 的 PP 变化分别为
-0.35%/+0.38% 及 -0.23%/-0.28%。所有生成输出均一致。
页锁定源初筛生成 2,048 token，速率为 172.8 与 172.6 tok/s；全主机源初筛生成
512 token，速率为 139.3 与 138.4 tok/s。这是两个不同工作负载。

## 额外专家辅助卡

单独的原型让另一个常驻专家层级与现有第一个辅助卡并行计算仅路由专家预填充行。
每个辅助卡使用现有 MMQ 传输及内核，返回独立、连续、未加权的行块，
并在原有逐 token 合并前完成同步。流式分块及受限融合对等路径保持不变。

此开发 A/B/B/A 测试的功耗上限为 400 / 320 / 250 W，RAM 专家副本为 20 GiB。
两个配置均分配额外辅助卡的缓冲区，只有候选配置向其派发计算。
GPU 专家布局保持为 7,669 / 9,331 / 7,576，解码时全部专家均可在 GPU 上使用。
额外缓冲区无需挤出专家。关闭复用、停放及自适应。
这些速率不能直接与前面使用 24 GiB RAM 副本的调查比较。

| 提示词 token 数 | 仅第一个辅助卡 | 两个辅助卡 | 变化 |
|---|---:|---:|---:|
| 256 | 460.0 tok/s | 953.2 tok/s | +107.2% |
| 512 | 662.3 tok/s | 1,269.1 tok/s | +91.6% |
| 1,024 | 866.8 tok/s | 1,469.6 tok/s | +69.5% |
| 2,048 | 1,198.5 tok/s | 1,625.0 tok/s | +35.6% |

每种长度、每个配置各测量四次。首层派发日志确认，256 token 请求在额外辅助卡上
计算 775–787 行，512 token 请求计算 1,310–1,313 行。
提示词最后一个 token 走解码路径，因此日志中的批处理长度为 255 和 511。

候选配置的全部 18 个回答均与对照的贪心文本一致，其中包括两次生成 2,048 token
的测试。单独使用原始二进制、相同 20 GiB RAM 预算的运行，与全部八个短提示词
对照的输出一致。生成速率为 170.2 与 172.8 tok/s，未观察到解码性能损失。
现有传输一致性测试在主卡与额外辅助卡之间通过了主 GPU 及 CPU 参考的容差检查。
运算 CUDA 内核、权重格式及合并顺序均未改变。

## 结果

仅调整调度的实验未达到任一短提示词目标。单独的受控测试通过计算另一个常驻层级的
专家，超过了 512 token 目标，并接近 256 token 目标。这是开发证据，
不代表广泛的质量或工作负载验证。原型引擎改动在该次测试后已还原。
后续[日常使用加固](extra-peer-prefill.md)记录受限额外层级路径、内存回退及完整 BF16 质量比较。
