# 双卡长提示词预填充

[English](../../precision/paired-prefill.md)

启用 `--prefill-native-next` 后，性能相近的主卡与第一张辅助卡可以对长提示词执行流水线计算，
同时将性能不同的第三张卡保留为专家层级。这条流水线按完整层分工，在层组之间传递残差行，
而不是每层都返回专家输出行。第三张卡保留原有的解码和短提示词计算职责。

## 选择条件与内存

新的选择规则仅适用于两张专家辅助卡、性能相近的前两张卡，以及 48 层、宽度为 2,560 的模型。
原有的双卡和全部卡性能相近时的选择规则保持不变。实测双卡布局由主卡处理第 0–25 层，
第一张辅助卡处理第 26–47 层；成本模型会先计入该约束，再决定是否拆分。
辅助卡的权重镜像覆盖启动时选择的更宽层范围。

分块上限为 32,768 token 时，能放进一个配置分块的提示词片段仍由主卡处理，
双卡路径从超过 32,768 个新 token 的片段开始具备使用条件。
其他分块上限保留两个分块的启用下限。这里统计新读取的 token，
而不是包含缓存部分的上下文总长度。图像、正在解码的槽位、不合适的链路
以及内存不足仍沿用原有的拒绝或回退规则。分块边界与仅主卡路径一致。
辅助卡的位置单元与运行状态传回后，最后一个分块在主卡上完成；解码前归还借用的专家槽位。

辅助卡临时镜像中的超连接矩阵使用与主卡完全相同的 HC8 反量化值。
启动时通过现有反量化器生成这些值，并写入镜像原有的 BF16 存储空间。
如果在这里加载原始 BF16 矩阵，计算结果就会与仅保留 HC8 的主卡不同。

## 检查点与中断读取

周期检查点合并各阶段的运行状态。启用 DFlash2 时，还会合并全部五个特征抽取层的最后几行，
然后在对应检查点位置保存草稿器状态。主卡的特征中转区使用映射的页锁定主机内存，
每张辅助卡使用临时显存缓冲区。在 2,048 行窗口和该模型宽度下，每个特征缓冲区为 100 MiB，
读取完成后释放。内存准入检查计入传输中的主机特征副本，并保留配置的空闲 RAM 下限。

中断读取时，先等待工作线程结束，再将已完成的辅助卡位置单元传回，最后释放临时存储。
这样，检查点恢复时既有运行状态，也有对应的位置单元。传回失败时，丢弃位置单元尚未可靠
保存的新检查点。会话文件格式、模型身份和磁盘缓存策略不变。

## 正确性检查

本节的流水线机制检查采用两个分块的启用下限；一个分块的启用边界由下文单独验证。

开发检查使用 RTX 3090 Ti / RTX 3090 / RTX 3080，强制功耗上限为 400 / 320 / 250 W。
算术比较时，三个层级分别固定保存 5,255 / 9,726 / 8,187 个专家，禁用自适应交换，
int8 KV 的全部容量驻留显存，RAM 专家副本为 20 GiB。
这避免弹性缓存扩缩把专家移到舍入方式不同的执行路径。

与之前的二进制比较，六次请求的 token ID 和全部 1,308 个已记录接受行的 logit 哈希完全相同：
长请求前后的短提示词、131,072-token 提示词、缓存与全新读取的 65,537-token 分支，
以及恢复读取的长提示词。这些续写合计生成 1,280 个 token。
这是对未改变算术的逐位检查，不是长上下文的绝对 BF16 质量测量。

专项测试覆盖 1、33 和 2,048 行的特征列合并、GPU 对映射缓冲区的实际读取、
320 × 10,240 与 10,240 × 320 两种 HC8 矩阵形状相对于 CPU 参考的比较、
按层范围传输状态和选择条件。Compute Sanitizer 在特征中转与阶段权重测试中报告零内存错误。
没有新增或修改生产算术内核。

在完成 32,768 个 token 后取消，再重试完整的 131,072-token 提示词，也能复现基线 token
及全部 262 个已记录 logit 哈希。磁盘缓存跨进程重启后复用 131,065 个 token，只读取七个；
续写和 logit 哈希同样一致。这些集成检查使用独立缓存目录。

## 一个分块的启用边界

预热后的进程内 A/B/B/A 诊断保持 32,768-token 分块上限、第 26 层切分下限、
固定 30 GiB RAM 专家副本和四个活动检查点，禁用自适应交换，且不复用提示词前缀。
磁盘缓存保持启用，使用独立目录。上述显卡的功耗上限为 400 / 320 / 250 W。
这些是代理运行的开发测量。

| 提示词片段中的新 token 数 | 相对于仅主卡处理的 PP 吞吐变化 |
|---|---:|
| 33,792 | +19.8% |
| 40,960 | +17.9% |
| 49,152 | +16.4% |
| 65,536 | +21.6% |

在配置上限以下，将请求额外细分为流水线分块并未确立普遍有效的收益。
保留的规则维持仅主卡路径的分块边界，不引入这种额外细分。

另一次固定专家位置的 A/B/B/A 检查在相同功耗上限下固定保存 6,077 / 9,717 / 8,192 个专家，
使用全驻留 int8 KV 和 30 GiB RAM 副本。32,769 个新 token 时，贪心续写和 logit 哈希不同；
49,152 时文本相同，但 logit 哈希不同。33,792 和 65,536 时两者均相同。
因此，即使权重格式与算术内核未改变，这次启用边界调整也不是在每种长度下逐位等价；
贪心输出可能改变。

常规 BF16 质量门禁使用 100 个 512-token 上下文、25,500 个评分位置、int8 KV、
完整 Q8_0 PLE 和固定 20 GiB RAM 副本，在相同功耗上限下禁用自适应交换。
两次运行的初始专家位置均为 7,669 / 9,331 / 7,576。
全部评分行与之前的测量完全一致。

| BF16 质量指标 | 之前 | 一个分块的启用边界 |
|---|---:|---:|
| PPL | 3.30383093 | 3.30383093 |
| 平均 KLD | 0.09661079 | 0.09661079 |
| Top-1 一致率 | 89.69020% | 89.69020% |

这一短上下文门禁不会运行跨卡路径，也不能确立实际 32K 上下文下相对于 BF16 的绝对质量。

## 开发性能

标准 `basalt-bench` 比较按 A/B/B/A 顺序运行，每个进程重复两次，使用 30 GiB RAM 专家副本、
四个活动提示词检查点，禁用自适应交换，不复用提示词前缀。基准测试关闭磁盘会话停放，
以单独测量调度；生产服务保留原有磁盘缓存配置，并单独检查。初始专家布局为
7,669 / 9,331 / 7,576。上述三张卡的功耗上限仍为 400 / 320 / 250 W。
这些是代理执行的开发测量，不是维护者公布的主要性能结果。

标称 128K 和 240K 的测试输入实际分别为 133,205 和 249,734 个 token。
下表按总 token 数除以引擎提示词耗时汇总。冷运行指每个新引擎的第一次重复，热运行指第二次。

| 输入 token 数 | 运行 | 之前版本 | 双卡流水线 |
|---|---|---:|---:|
| 133,205 | 冷 | 4,382 tok/s | 4,736 tok/s |
| 133,205 | 热 | 4,358 tok/s | 5,359 tok/s |
| 249,734 | 冷 | 4,046 tok/s | 5,297 tok/s |
| 249,734 | 热 | 4,031 tok/s | 5,927 tok/s |

冷运行在 KV 增长期间的专家布局一致：中间深度时主卡保存 6,962 个专家，KV 完全分配时为
6,326 个。缩小 KV、进入热运行时，之前版本的缓存重新增长到 7,554 个槽位，
而流水线因额外分配只能增长到 7,549 个。因此热运行数据包含这个小幅布局差异，
与上面固定层级布局的算术检查分开记录。

散文测试中，每个版本都用 2,048 个验证窗口生成 4,552 个 token，
其中包括第一次长上下文测试之后的生成。平均窗口时间从 21.899 ms 变为 21.663 ms，
即从每秒 45.664 个窗口变为 46.162 个；生成速度为 101.50 与 102.60 tok/s。

另一个仅测试短提示词的 A/B/B/A 检查采用相同配置和初始专家布局，每个进程重复四次，
不发生 KV 扩缩。标称 512 / 4K / 8K 的测试输入实际为 549 / 4,191 / 8,353 个 token。
排除每个进程第一次重复后的热运行速度，之前版本为 1,185.49 / 1,692.76 / 2,142.57 tok/s，
流水线版本为 1,179.84 / 1,698.07 / 2,142.81 tok/s，变化为 −0.48% / +0.31% / +0.01%。
冷运行速度分别为 739.19 / 1,575.09 / 2,114.07 与 728.79 / 1,568.63 / 2,114.07 tok/s。
这些小幅差异尚不能证明短提示词路径加速。

标准测试输入比较中的最佳长请求为 5,973 tok/s。另一组源码输入筛选测试采用相同功耗上限、
30 GiB RAM 专家副本和四个检查点，先读取恰好 32,768 token 的预热请求，
再读取全新的 131,072 与 245,760 token 提示词，分别测得 5,964 和 6,289 tok/s，
提示词 token 复用均为零。这表明预热后可以超过 6,000 tok/s，
但不能证明所有测试输入或冷请求都能达到该速度。

一次 131,072-token 的 Nsight 诊断运行使用 29 GiB RAM 专家副本，给分析器留出空间，
功耗上限相同。主卡与辅助卡的内核忙碌时间分别为 18.60 和 10.57 秒。
最终验证前的 4.73 秒内核空档中，主卡有 8.30 GB 的主机到设备复制，
表明专家缓存归还是后续优化目标。页锁定上传环形缓冲区试验没有改善保留路径，因此未纳入。

一次实际服务检查保留自动专家/RAM 容量规划、自适应交换和磁盘停放。
全新 131,072 与 245,760 token 请求分别测得 4,762 和 5,585 tok/s；
预热后另一个全新 245,760 token 请求测得 5,839 tok/s。
重复兼容提示词时，复用 245,753 个 token，只用 166 ms 读取七个，八个续写 token 完全相同。
因此，全部这些配置都启用时，实际服务吞吐量仍低于隔离基准测试的峰值。
