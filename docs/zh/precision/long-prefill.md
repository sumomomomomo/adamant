# 原生专家权重的长提示词预填充

[English](../../precision/long-prefill.md)

默认关闭的诊断参数 `--prefill-native-next` 启用实验性 Q5_0 下投影及 v2 IQ4_XS
门控/上投影，不是推荐的服务设置。正常路径保留原有内核与阈值。启用诊断后，
原生融合预填充路径除 Q2_0、IQ4_NL 外，还支持 Q5_0 下投影。在混合
UD-IQ4_XS 模型包上，融合覆盖范围从 13 个专家层扩展到全部 48 层。完全融合的
大分块比 MMQ 回退路径需要更少的临时内存，因此在实测机器上可使用 32,768 token 分块。

## 执行与精度

Q5_0 块直接解码为有符号整数编码及其原始缩放值。v2 下投影内核把原始块读入
共享内存，再解码为 MMA 片段。IQ4_XS 门控/上投影采用相同的 v2 调度：每个原始
单元保存 128 个值的编码，超级块的缩放元数据单独复制。IQ3_XXS 门控/上投影与
IQ4_NL 下投影保留原有 v2 实现。

当分块至少为 16,384 token 时，流式环形缓冲区保存 384 个专家块，完全融合的
分块也适用。较小的流式分块仍使用 256 个槽位，使权重传输能持续覆盖较长的注意力阶段。

权重及其量化、完整 Q8_0 PLE 表、int8 KV 格式均不变。融合激活量化及 v2 累加
顺序可能与旧 MMQ 路径不同。这属于数值变化，不保证 logits 逐位相同或贪心回答完全一致。

大分块专家辅助路径仍以 4,096 行为上限，但启用诊断后的实验性格式覆盖包括 Q5_0。在实测机器
上，更长的读取可使用[双卡流水线](paired-prefill.md)，由各卡分别处理完整的层。
两个专家层级均计算路由行时，额外辅助卡使用
[实验性三 GPU 阈值](peer-prefill-cutoffs.md)。三 GPU 解码、DFlash2、视觉及对话缓存
序列化保留现有路径。

## 验证方法

内核检查使用随机原生权重块（包括负 Q5_0 缩放值），与原有 MMQ 路径及双精度
累加的 CPU 参考对比。测试覆盖全零输入、偏斜路由、未使用专家、非对齐权重块和
不同专家范围。计时包含真实的 2,560/640 维度、512 个专家、top 10 及最高
32,768 token 分块。对等传输也检查新格式组合与仅主卡计算的专家输出是否一致。

BF16 质量参考包含 100 个 512 token 上下文，共评分 25,500 个位置。诊断参数
`--diag-prefill-long` 要求同时提供 `--ppl-base`，强制其 256 token 前缀使用流式
运算，不影响正常服务的阈值。这样能通过真实解码质量检查覆盖变更的运算，但它
并非 32K 上下文的 BF16 参考测量。

开发阶段的服务对比采用旧/新/新/旧交替运行，固定相同的专家放置与 RAM 副本，
禁用自适应和提示词复用。RTX 3090 Ti / RTX 3090 / RTX 3080 的功率上限分别为
400/320/250 W。冷启动与热运行请求分别记录，稳态速率排除预热请求。

下方性能与质量结果仅为该机器上的开发测量，不代表通用性能承诺。

## 开发测量结果

服务 A/B/B/A 对比使用 32,768 个未缓存输入 token、int8 KV、完整 Q8_0 PLE、
固定 20 GiB RAM 专家副本，以及 7,669 / 9,331 / 7,576 个驻留专家。上述三张卡
的功率上限为 400 / 320 / 250 W。旧版本分块上限为 16,384 token，实验版本为
32,768。每个进程先预热三次，再测量两次长请求。这测量权重与文件缓存预热后的
吞吐率，未复用 token 前缀，不代表冷启动吞吐率。

| 引擎指标 | 旧版本 | 实验版本 | 变化 |
|---|---:|---:|---:|
| 32,768-token 预填充 | 3,714.7 tok/s | 4,510.9 tok/s | +21.43% |
| 512-token 预填充 | 1,073.7 tok/s | 1,058.4 tok/s | -1.43% |
| 4,097-token 预填充 | 1,113.5 tok/s | 1,277.8 tok/s | +14.76% |
| 512-token 提示词后的 2,048-token 生成 | 120.83 tok/s | 119.60 tok/s | -1.02% |

四次生成回答完全相同，均有 717 个验证窗口，1,865 个提议中接受 1,331 个。
按 A/B/B/A 顺序，平均窗口耗时为 23.43 / 23.69 / 24.08 / 23.85 ms
（42.68 / 42.21 / 41.53 / 41.93 窗口/秒）。这些测量未证明解码零开销，
也未达到 5,000 tok/s 目标。 另一次独立解码 A/B/B/A 检查在两个版本上均使用
16,384-token 分块上限，测得 118.68 与 117.63 tok/s（-0.89%），回答仍完全相同。
四次均有 744 个窗口，1,873 个提议中接受 1,305 个；窗口耗时分别为
23.02 / 23.14 / 23.66 / 23.37 ms。GPU 功率上限仍为 400 / 320 / 250 W。
首次尝试的复测与 CPU 编译重叠，未纳入此比较。

另一次仅调整设置的检查在旧二进制上使用 32,768-token 上限，预热后约为
3,990 tok/s。带诊断开关的实验重构建复测约为 4,514 tok/s。这些单进程检查
佐证结果，但不是上述交替对比。全局默认值保持不变。

在相同功率上限下，IQ4_XS/Q5_0 专家微基准使用 32,768 token、2,560/640 维度、
512 个专家、top 10，MMQ 耗时 49.228 ms，新 v2 内核为 35.528 ms。每层逻辑
门控/上投影/下投影工作量为 3.221 TFLOP，对应约 65.4 与 90.7 有效 TFLOP/s。
这里不包含注意力、稠密计算及权重传输。在开发主机上，变更的 CUDA 翻译单元
通过 `nvcc --time` 测得编译耗时 6.43 秒。

所有原生 CPU/MMQ 参考测试、对等传输逐字节一致性测试，以及批宽/位置不变性
检查均通过。Compute Sanitizer 在 IQ4_XS 测试组报告零内存错误。未变更的普通
短路径质量检查中，5,100 个评分位置与旧版本完全一致。

新 v2 参考组合在随机输入上的最大绝对/逐点相对误差如下（256 token、64 个专家，
相对误差分母下限 `1e-6`；功率上限 400 / 320 / 250 W）：

| 门控/上投影 + 下投影 | 对 CPU 最大绝对误差 | 对 CPU 最大相对误差 | 对 MMQ 最大绝对误差 | 对 MMQ 最大相对误差 |
|---|---:|---:|---:|---:|
| IQ3_XXS + Q5_0 | 53.3757 | 33,678.1 | 3.15881 | 26.7957 |
| IQ4_XS + Q5_0 | 14.8402 | 48,717.3 | 1.40591 | 23.5764 |

接近零的参考值会放大逐点相对误差。相对 CPU 的相对 RMS 为 0.01440 / 0.01455，
与 MMQ 相当；v2 相对原融合实现为 0.00005942 / 0.00004451。下文单独评估整模型质量。

## 质量限制

下表两列都强制同一 BF16 参考的 256-token 前缀采用流式运算，专家放置、int8 KV、
完整 Q8_0 PLE、20 GiB RAM 副本及 400 / 320 / 250 W 功率上限相同。每列均评分
全部 100 个分块（25,500 个位置）。旧运算列是使用原有内核构建的诊断对照，
避免把 CPU 与流式预填充的差异混入比较。

| 指标 | 旧流式运算 | 实验流式运算 |
|---|---:|---:|
| PPL | 3.30193750 | 3.30826788 |
| BF16 平均 KL 散度 | 0.09665480 | 0.09611791 |
| BF16 top-1 一致率 | 89.70196% | 89.76471% |

PPL 上升 0.1917%，KL 散度与 top-1 一致率改善。未满足探索性设置的 0.1% PPL
绝对漂移容限。该容限是开发阶段的选择，不是既定的项目阈值。按分块配对估算，
PPL 变化的近似 95% 区间为 -0.070% 至 +0.454%；这些测量既未证明普遍的质量
下降，也未证明等价，并且未在真实 32K 上下文测量 BF16 一致性。因此这些内核
保留为诊断实验，不替换正常路径。

长分块专家拆分、对等卡本地求和、稀疏专家启动、更小的流水辅助分块、512 槽
环形缓冲区，以及更大的专家启动批次，均未改善保留方案的端到端结果，未纳入。
减少暂存预留后，RAM 自动增长引发了内存压力，该规划器变更也未纳入。更大的
提示词分块可能延迟取消响应，因为现有取消检查在分块边界进行。
