# DFlash2 精度

[English](../../precision/dflash2.md)

[服务与转换](../dflash2.md)

DFlash2 只提出候选。现有目标验证器、惩罚、语法遮罩和采样器决定每个输出 token。
移植增加了只读目标特征捕获，不改变目标权重、运算或状态更新。
比较时必须固定实际专家布局：草稿模型改变可用显存，自动布局可能改变专家归约顺序。

图像请求保留现有目标视觉及 M-RoPE 处理。DFlash2 捕获图像行 HC 特征，
并按逻辑行序号索引私有注意力。这两套坐标独立，包括缓存恢复后的处理。

## 草稿运算

运行时文件使用 Q8_0 投影矩阵、平面 int8 激活和 F32 激活缩放。
归一化、动态卷积、旋转位置和注意力使用 F32 累加。
前驱和后继码本保留 BF16。转换中的 Q8_0 编码采用最近舍入，中点取偶数。
共享的完整目标嵌入表和输出头保留现有格式。

私有 KV 环以 F32 保存键和值。HC 平均值来自目标层完成后的输出。
延迟 FFN 写入的捕获直接计算平均值，不修改残差；加法重组可能与逐流写入后再平均
有细微差异，仅影响候选。

## 开发验证

CUDA 内核一致性测试在 sm_86 的 RTX 3090 Ti、RTX 3090 和 RTX 3080 上通过。
所有受测运算都使用真实模型尺寸并对照 CPU 双精度参考；量化输出允许半个量化步长
加浮点误差。HC 捕获还与现有门控写入内核比较。

在 RTX 3090 Ti 上，与现有写入比较的捕获最大绝对误差为 `4.77e-7`。
受测矩阵中，Q8 GEMM 相对双精度点积的最大绝对误差为 `6.72e-5`。
参考值接近零时相对误差可能较大；测试同时报告绝对和相对最大值。

独立的 FP32 PyTorch 参考使用原始 BF16 草稿权重，在随机 2,300 token 上下文和
4,096 行合成输出头上进行比较。最终行余弦相似度为 `0.98791` 至 `0.99671`，
七个选择器 token 中六个相同。该比较包含草稿权重和激活量化，不是目标模型质量测量。

内核计时是开发测量，三张卡的功耗上限分别为 375 W / 320 W / 250 W。
真实尺寸注意力内核每次调用约为 55 / 65 / 70 微秒；3090 Ti 上受测最大融合投影
约达到 735 GB/s。这些是微基准，不代表端到端速度。

固定主卡 16.0 GiB 专家层级、使用单 GPU 并关闭自适应后，
MTP 与 DFlash2 的全部 384 个受测贪心 token 完全一致。
这样可以排除自动布局变化对目标运算比较的影响。

DFlash2 服务已通过对抗性 JSON Schema 检查，包含候选被拒绝后的遮罩重采样。
验证命令见[服务页面](../dflash2.md)。

## 缓存状态的精确性

草稿快照逐字节保存 F32 K/V，不量化缓存；只保留下一次查询可能使用的最后
2,047 个已提交行。恢复前验证完整草稿权重内容派生的身份、逻辑位置、尺寸和载荷长度。
这些操作不改变目标运算。

在 7 行及 2,300 行上下文中，覆盖整个私有环后再恢复，候选 token、概率及最终行
浮点值均逐位相同。服务检查涵盖图像后的多轮对话、超过局部窗口的历史、RAM 切换
以及磁盘重启恢复。冷启动与缓存恢复的贪心回答一致；更换图像只复用未变化的前缀。
